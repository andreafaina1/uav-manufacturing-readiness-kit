# Lean Production System Starter

This module helps an early-stage hardware team avoid scaling an improvised prototype-build environment into a fragile production system.

## 1. 6S + Security
The app uses the familiar 6S structure — Sort, Set in Order, Shine, Standardize, Sustain, Safety — plus a separate **Security & information control** lens. Security is deliberately kept distinct rather than presented as a canonical seventh S.

## 2. Ten-lens waste walk
The first eight lenses use the common DOWNTIME mnemonic:

1. Defects
2. Overproduction
3. Waiting
4. Non-utilized talent
5. Transportation
6. Inventory
7. Motion
8. Extra-processing

For hardware scale-up the kit adds two explicit risk/waste lenses:

9. Safety & ergonomics exposure
10. Information / configuration loss

The last two are useful extensions for the toolkit; they are not presented as a universally canonical Lean list.

## 3. Minimum Viable Production System (MVPS)
Before increasing rate, the team checks eight gates:

- Product
- People
- Process
- Place
- Parts
- Tools
- Quality
- Performance

The objective is not to build a full factory prematurely. It is to build **one excellent production cell** that can teach the team how to scale.

## 4. First-batch cell design
A pragmatic first flow is:

**Kit → Prepare → Assemble → Integrate → Configure → Inspect → Test → Release**

For every stage define:
- entry condition
- required parts/tools/information
- standard work sequence
- expected cycle time
- acceptance evidence
- standard WIP / FIFO location
- next destination

## 5. Operating system
Recommended lightweight routines:
- pre-kitting and shortage visibility
- point-of-use storage
- standard work and visual work instructions
- FIFO and WIP limits
- quality at source / poka-yoke where practical
- daily or weekly SQDCP review: Safety, Quality, Delivery, Cost, People/Problems
- defect Pareto and root-cause/countermeasure loop
- skills matrix and cross-training
- Kaizen backlog with owner and validation date

The purpose is to make abnormalities visible early and avoid scaling hidden queues, expert dependency, rework, unsafe work or configuration confusion.
